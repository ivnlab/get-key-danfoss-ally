# С нуля: если у вас есть только IP шлюза

Этот файл написан в предположении, что на компьютере нет вообще ничего
из нужного - ни Python, ни adb, ни эмулятора. Если что-то из перечисленного
уже стоит - соответствующий шаг просто пропускается.

Каждый шаг - что сделать и как проверить, что он прошёл успешно, прежде
чем переходить к следующему.

## Шаг 0. Получить сами файлы инструмента

На странице репозитория на GitHub: зелёная кнопка **Code → Download ZIP**,
распаковать куда угодно (например, `C:\danfoss_local`). Дальше все пути в
этой инструкции - относительно этой распакованной папки.

(Если вместо этого установлен git - можно `git clone` вместо скачивания
zip, но для одного разового использования это не обязательно.)

## Шаг 1. Python

Скачать с [python.org/downloads](https://www.python.org/downloads/)
(любая текущая версия), при установке отметить галочку **"Add python.exe
to PATH"**.

Проверка (открыть PowerShell, набрать):
```powershell
python --version
```
Должна вывестись версия, например `Python 3.12.4`. Если пишет "не
распознано как команда" - Python не в PATH, переустановить с отмеченной
галочкой выше.

## Шаг 2. adb (Android Debug Bridge)

Отдельно ничего скачивать не нужно - сами скрипты умеют находить `adb`
сами: сначала смотрят PATH, потом рядом с собой, потом в папке LDPlayer
(она появится после шага 3) и в стандартных местах установки Android SDK.
Если ни один из вариантов не подойдёт - `check_env.py` (шаг 6) прямо
скажет об этом и подскажет, что сделать.

## Шаг 3. Рутованное Android-устройство

Нужен рутованный Android - реальный телефон, которым не жалко жертвовать
ради root, либо эмулятор на компьютере. Эмулятор проще - на нём и
расписан весь дальнейший путь. Весь этот путь проверялся конкретно на
**Windows 11 (сборка 10.0.26100)** и **LDPlayer 14.0.18.0** - на других
версиях Windows/LDPlayer или реальных телефонах не проверялось, может
отличаться в деталях.

**Root не включён по умолчанию** - это отдельный шаг, без него `adb shell
su` не сработает даже при полностью рабочем эмуляторе.

1. Скачать и установить [LDPlayer](https://www.ldplayer.net/) (или любой
   похожий эмулятор с поддержкой root - но конкретно этот путь проверялся
   именно на LDPlayer 14.0.18.0).
2. Запустить эмулятор, дождаться полной загрузки Android внутри него.
3. Открыть настройки самого LDPlayer (значок шестерёнки в боковой панели
   инструментов эмулятора, не Android-настройки внутри), вкладка **Basic
   settings**, найти **Root permission** (формулировка может немного
   отличаться в других версиях LDPlayer) и включить его.
4. Перезапустить эмулятор (кнопка перезагрузки в той же панели), чтобы
   root применился.

Подключение и root проверяются вместе со всем остальным в шаге 6 -
отдельно вручную ничего вводить не нужно.

## Шаг 4. Приложение Danfoss Ally

Внутри эмулятора (или на телефоне) - открыть Play Маркет, установить
**Danfoss Ally**, залогиниться своим обычным аккаунтом. Открыть список
устройств и убедиться, что показывает живые данные (температуры и т.п.),
а не пустой экран или "загрузка".

## Шаг 5. Python-пакет frida

В PowerShell:
```powershell
pip install frida
```

## Шаг 6. Проверить, чего не хватает

В папке инструмента (из шага 0):
```powershell
cd C:\danfoss_local\tools\get_local_key
python check_env.py
```
На этом этапе всё должно быть `[OK]`, кроме `frida-server binary` и
`frida-server running` - его ставим следующим шагом. Скрипт сам напечатает
точную ссылку на нужный файл (версия и архитектура уже подобраны под ваше
устройство) - она будет выглядеть примерно так:
```
https://github.com/frida/frida/releases/download/17.16.4/frida-server-17.16.4-android-x86_64.xz
```

## Шаг 7. Установить frida-server на устройство

1. Перейти по ссылке из вывода `check_env.py` в браузере, скачается файл
   `.xz`.
2. Windows не умеет распаковывать `.xz` без сторонней программы - поставить
   [7-Zip](https://www.7-zip.org/) (если ещё не стоит), правой кнопкой по
   скачанному файлу → 7-Zip → Extract Here. Иногда после этого получается
   файл `.tar` вместо готового бинарника - тогда повторить Extract Here
   ещё раз уже над ним. В итоге должен получиться файл без расширения
   (или с `.exe`-подобной иконкой) с именем вроде `frida-server-17.16.4-
   android-x86_64` - его для простоты можно переименовать в `frida-server`.
3. Загрузить на устройство и запустить - три команды `check_env.py` уже
   напечатал вам в предыдущем шаге вместе с правильным путём к `adb`,
   их и выполнить как есть (замена `frida-server` на реальный путь к
   распакованному файлу может понадобиться, если он лежит не в текущей
   папке).
4. Проверить, что всё встало на место:
   ```powershell
   python check_env.py
   ```
   Теперь должно быть `[OK]` по всем пунктам, и внизу -
   `Environment looks ready.`

## Шаг 8. Запуск

```powershell
python cli.py --ip <IP шлюза>
```
Дальше скрипт сам ведёт по шагам: попросит открыть в приложении карточку
шлюза (просто посмотреть, ничего не нажимать) и нажать Enter, просканирует
память и в конце выведет в этом же окне готовый кусок текста для
`credentials.py`.

Если что-то на любом шаге пошло не так - подробный разбор частых проблем
в [README.ru.md](README.ru.md) в этой же папке.
